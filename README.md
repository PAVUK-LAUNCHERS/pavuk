«А что если наваять лаунчер под мою новую любимую игру, чтобы не пришлось закрывать зомби-клиенты через таск-менеджер, ну и после выхода сразу давались айпишники для переподключения?»

## Технические особенности

`СТАТУС: реализовано и стабильно`

- **Архитектура: два независимых исполняемых контура.** Lifeweb (Lifeweb II) и Scorcher (Scorcher: The Harmony) — раздельные Electron-процессы, раздельные хранилища настроек, раздельные точки входа. Пересечение — только общий IPC-канал (`preload.js`) и общий пул ресурсов. Кросс-влияние между контурами исключено по конструкции.
- **Подавление фантомных процессов.** Перед каждым запуском целевого клиента выполняется принудительная терминация зависших экземпляров `dreamseeker.exe`. Состояние отслеживается конечным автоматом: `IDLE → LAUNCHING → PLAYING → IDLE`. Возврат интерфейса на экран при завершении игры — гарантирован, без ручного вмешательства оператора.
- **Прямой доступ к точкам подключения.** Инициация `byond://`-соединения — в один клик, без промежуточного слоя браузера.
- **Плановая автоматизация.** Задаётся целевой сервер и временная метка — соединение инициируется без участия оператора в указанный момент.
- **Региональная маршрутизация (RZ / IZ).** Переключение сообщества меняет порты подключения на лету, без пересборки и переустановки клиента.
- **Управление ресурсами в фоновом режиме.** При сворачивании интерфейса все затратные процессы — видеодекодирование, canvas-рендеринг шума, SVG-анимации — принудительно приостанавливаются и возобновляются только при возврате окна в активное состояние. Фоновое потребление памяти удерживается в контролируемых пределах.
- **Визуальный слой — вариативен, функциональный слой — идентичен.** Lifeweb: холодная эстетика, сканлайны, стохастические вспышки. Scorcher: термальная палитра, зернистый шум, блокирующая последовательность перед запуском. Оба контура подчиняются одной и той же логике ядра.
- **Проверка версий — асинхронная, ненавязчивая.** Источник истины — GitHub Releases. Уведомление выводится, принудительное обновление — не предусмотрено. Решение оператора остаётся за оператором.
